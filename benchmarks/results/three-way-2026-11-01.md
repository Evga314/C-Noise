## Methodology / Методика

- Inputs are generated once per workload and batch size using fixed seeds.
- All contenders reuse the same input arrays for a given workload and size.
- Native contexts, FFM handles, reference objects and output arrays are created outside measured iterations.
- Every workload/size passes a complete raw-bit gate before any timing.
- A mismatch stops execution and is recorded; no timings are published for a failed run.
- Timings cover complete batch evaluation and are normalized to ns/point.
- Checksums are calculated outside timed intervals.
- Measurement order rotates between contenders.
- This is a standalone microbenchmark, not JMH. Results are specific to the recorded machine and runtime.

## Workloads / Нагрузки

- **W1 Perlin:** Minecraft `PerlinNoise.get` versus scalar native Perlin FFM sampling. The native contender performs one scalar downcall per point; it is not a native batch API.
- **W2 Arithmetic:** recursive object-tree interpreter, explicit Java batch loop, and native `ArithmeticProgram` batch.
- **W2 operation count:** 36
- **W2 native instruction count:** 70
- **Batch sizes:** [256, 4096, 32768, 65536]
- **Warmup:** 5 iterations per contender and size.
- **Measurements:** 15 iterations per contender and size.

## Conclusion / Заключение

На этой машине Java reference выигрывает W1 у native scalar FFM на всех размерах: по медиане в 1.78×, 1.96×, 1.82× и 1.65× соответственно для 256, 4096, 32768 и 65536 точек. В W2 optimized Java batch — самый быстрый участник на всех размерах; существующий native arithmetic batch медленнее него в 8.42×, 25.59×, 36.23× и 34.12×. Native проигрывает object-tree Java на 256 точках (259.766 против 225.781 ns/point), но опережает его на остальных размерах примерно в 1.20×, 1.23× и 1.33×. Таким образом, преимущество текущего нативного движка перед оптимизированным Java batch не подтверждено: наблюдаемый разрыв велик, это не результат «в пределах шума». Небольшой выигрыш относительно объектного дерева нельзя считать доказательством преимущества архитектуры в целом. Это один запуск JVM, минимальный заданный прогрев и синтетическая арифметическая программа; заметное расхождение медиан и минимумов ограничивает точность коэффициентов. W1 включает scalar FFM downcall на каждую точку, W2 — существующий скалярный C-интерпретатор с пакетным API и копированием массивов. Результаты не измеряют будущую tile/SoA VM и не доказывают её ускорение на реальных density trees; дальнейшая оптимизация должна сравниваться именно с optimized Java baseline.
